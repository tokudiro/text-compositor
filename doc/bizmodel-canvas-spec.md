# bizmodel 記法仕様（記法2: ビジネスモデルキャンバス）

状態: ドラフト（Issue #458）。実装前の仕様案であり、DSLの文法・配置の数値は、変わりうる。

記法1（モノ・カネの流れ。`doc/bizmodel-notation-spec.md`）と同じ、`bizmodel`のフェンス・拡張子・設定のキーで扱う。本文の冒頭に`type canvas`と書くと、この記法になる。

## 1. 範囲

- ビジネスモデルキャンバスの、9つの枠に、箇条書きの文字を入れた図を描く。
- 対象外: Value Proposition Canvas、ロゴ、元の図そのもの、枠ごとの色・アイコン・付箋の見た目、画像の埋め込み。
- 描くのは、枠の名前と配置だけである。図形は、自前で描く。

## 2. 出典と利用条件

Strategyzerの公式ページ「Usage of our tools」（https://www.strategyzer.com/legal/usage-of-our-tools）の記載にもとづく（2026-10-14確認）。

- Business Model Canvasは、Creative Commonsで公開されている（配布物の表記は、CC BY-SA 3.0 Unported）。利用・変形は自由で、条件は、出典の明示である。
- 出典の明示は、「Strategyzer.com」の文字を、**すべてのキャンバスの下に、はっきり読める形で**示す。
- したがって、**生成するすべての図の下に、出典の表記を入れる。利用者が、消したり、変えたりできない。**
- 表記の文面: `Business Model Canvas: Strategyzer.com (CC BY-SA 3.0)`
- ソフトウェアへの組み込みについて、公式は、「事前の連絡が望ましい」と述べている（推奨）。連絡は行わない（#458で決定）。
- 名称は、機能の説明として「ビジネスモデルキャンバス」と書く。製品名・識別子・コマンド名には、使わない。

## 3. 枠

| キー | 略号 | 見出し（日本語） |
|---|---|---|
| `partners` | KP | パートナー |
| `activities` | KA | 主要活動 |
| `resources` | KR | リソース |
| `value` | VP | 価値提案 |
| `relationships` | CR | 顧客との関係 |
| `channels` | CH | チャネル |
| `segments` | CS | 顧客セグメント |
| `costs` | C$ | コスト構造 |
| `revenue` | R$ | 収益の流れ |

- 見出しは、`見出し（略号）`の形で、枠の上に出す（例: `価値提案（VP）`）。
- 見出しの日本語名は、機能を表す語で、自前に付けた（公式の訳に依存しない）。

## 4. DSL

```
type canvas
title "ダイソー"
segments "一般顧客"
value "手軽さ、安さ！（全100円）"
channels "店舗販売"
revenue "商品売り上げ（1個100円）"
```

| 文 | 書き方 | 意味 |
|---|---|---|
| 記法の種類 | `type canvas` | 1行目に書く。記法1（`flow`）との切り替え |
| 題名 | `title "…"` | 省略できる。1回だけ |
| 箇条書き | `キー "…"` | そのキーの枠に、1項目を足す |
| コメント | `# …` | 行頭にも、行の途中にも書ける |

- 同じキーを、複数回書ける。書いた順に、枠の中に、箇条書きで並ぶ。
- 文を書く順は、自由。枠ごとに、まとめて書く必要はない。
- 書かなかった枠は、空の枠として描く。
- 文字は、`"…"`で囲む。`\"`と`\\`は、エスケープとして読む（記法1と同じ）。日本語を、そのまま書ける。
- 項目の中の改行は、書けない（1項目は、1行）。長い項目は、描画時に、枠の幅で折り返す。
- 項目の数・長さに、上限は設けない。枠は、内容に応じて、高さが伸びる。

## 5. 配置

標準のキャンバスと同じ配置にする。5列で、上段が7つの枠、下段が2つの枠である。

```
+---------+---------+---------+---------+---------+
|         |  KA     |         |  CR     |         |
|   KP    +---------+   VP    +---------+   CS    |
|         |  KR     |         |  CH     |         |
+---------+---------+---------+---------+---------+
|      C$ (コスト構造)  |      R$ (収益の流れ)     |
+------------------------+------------------------+
```

- KP・VP・CSは、上段の2行にまたがる。KA・KR（2列目）と、CR・CH（4列目）は、上段の各行に1つずつ。
- C$とR$は、下段の、左右の半分ずつ。
- 5列の幅は、等しい。行の高さは、各行の枠の内容の高さの最大値（最小値あり）で決まる。またがる枠は、2行の合計高さを使う。
- 内容がまたがる2行の合計高さより高いときは、2行の高さを、均等に増やす。

### 5.1 文字の折り返し

- 1項目は、先頭に「・」を付けて、枠の幅（余白を除く）に収まるまで、折り返す。折り返した行は、「・」の分だけ、字下げする。
- 幅の見積もりは、記法1と同じ（全角は1em、半角は0.55em）。フォントは測らない。
- 日本語は、文字の間のどこでも折り返せる（禁則処理は、行頭の`、。）」`などを、行頭に出さない程度の簡易なもの）。英数字の語は、空白で折り返し、1語が枠より長いときは、語の途中で切る。

## 6. 描画

- 黒の単色の線画。枠は、白地に、黒の細い線。
- 見出しは、太字で、枠の左上。本文は、見出しの下に、左寄せ。
- 全体の下に、出典の表記を、1行で、中央に置く（2章）。他の文字より小さいが、読める大きさ（本文の0.85倍以上）にする。
- 題名があれば、図の上に、中央に置く（記法1と同じ）。
- 図には、`<title>`（題名。無ければ`business model canvas`）を入れる（代替テキスト）。

## 7. エラー

エラー番号は、記法1と共通である。

| 番号 | 内容 | 例 |
|---|---|---|
| E02 | 項目の文字が空 | `value ""` |
| E06 | 構文エラー | 未知のキー、文字が無い（`value`だけ）、閉じていない`"`、`type`の位置・値の誤り、記法1の文（`company`・`->`・`bundle`など）を書いた |
| E08 | 内容が1つもない | 箇条書きが、1つも無い |

- 記法1の文（`company`など）が書かれていたときは、`type canvas`と矛盾していることを、メッセージで示す。
- エラーには、行と桁を含める。

## 8. AST（JSONにできる形）

```json
{
  "type": "canvas",
  "title": "ダイソー",
  "blocks": {
    "partners": [],
    "activities": [],
    "resources": [],
    "value": [{"text": "手軽さ、安さ！（全100円）", "line": 4}],
    "relationships": [],
    "channels": [{"text": "店舗販売", "line": 5}],
    "segments": [{"text": "一般顧客", "line": 3}],
    "costs": [],
    "revenue": [{"text": "商品売り上げ（1個100円）", "line": 6}]
  }
}
```

- `blocks`は、9つのキーを、常にこの順で持つ。
- 記法1のASTと、`type`で区別する（`flow`・`canvas`）。

## 9. 決定と未決

### 決定済み（2026-10-14）

- Strategyzer AGへの事前の連絡は、行わない（#458）。出典の表記を、すべての図の下に、消せない形で入れる。
- Value Proposition Canvasは、対象外。
- DSLは、`キー "文字"`の文を、1行1項目で書く。キーは、英語の9語。

### 未決

- 実際の見た目の数値（列の幅・文字の大きさ・余白）。実装時に、サンプルを見て決める。
- 項目ごとの強調（#459）への対応。
