# フローチャート（flowchart）

`flowchart`は、JIS X 0121（ISO 5807と対応）の図記号に準じたフローチャートを、字下げの短いテキストから描きます。Markdownの` ```flowchart `フェンスと、単体ファイル（`.flow`）の両方で使えます。外部ツール（ブラウザ・Java）は要りません。

上から下へ、疑似コードのように書きます。順次・分岐・繰り返しを、字下げで表します。

> Mermaidのフローチャート（`flowchart TD`など）とは、別の記法です。Mermaidの記法で書く図は、これまでどおり、` ```mermaid `で書きます。

## 最初の例

```text
start
注文を受ける
judge 在庫がある?
  はい: 出荷する
  いいえ: 取り寄せる
請求書を作る
end
```

```flowchart
start
注文を受ける
judge 在庫がある?
  はい: 出荷する
  いいえ: 取り寄せる
請求書を作る
end
```

- 1行に、図記号を1つ書きます。
- `start`と`end`は、端子（開始と終了）です。文字を省くと、その言葉（`start`・`end`）が出ます。
- キーワードのない行は、処理（長方形）です。
- `judge`は、判断（ひし形）です。次の行から、1段深く字下げして、分岐を書きます。

## 図記号

| キーワード | 図記号（JIS X 0121） | 形 | 使いどころ |
|---|---|---|---|
| `start`・`end`・`terminal` | 端子 | 角丸の長円 | 開始・終了・外部との出入り口 |
| （なし）・`process` | 処理 | 長方形 | 演算や処理 |
| `judge` | 判断 | ひし形 | 条件で道が分かれるところ |
| `data` | データ（入力・出力） | 平行四辺形 | 入力にも出力にも使います（媒体を問いません） |
| `sub` | 定義済み処理 | 左右に縦線のある長方形 | サブルーチンや、別の場所で定義した処理 |
| `prep` | 準備 | 六角形 | 初期値の設定など |
| `loop`〜`endloop` | ループ端（始端と終端） | 上（または下）の2つの角を落とした長方形 | 繰り返し（下の「繰り返し」） |
| `doc` | 書類 | 下の辺が波線の長方形 | 帳票などの、人が読む書類 |

```text
start
prep 合計を0にする
loop 注文処理: 注文がなくなるまで
  data 注文を入力
  sub 在庫を確認する
  注文を1件処理する
endloop
doc 売上帳票を出力
end
```

```flowchart
start
prep 合計を0にする
loop 注文処理: 注文がなくなるまで
  data 注文を入力
  sub 在庫を確認する
  注文を1件処理する
endloop
doc 売上帳票を出力
end
```

規格には、ほかにも記号（手作業・手操作入力・表示・結合子など）があります。まだ使えません。形の大きさの比率（角を落とす大きさ、波の高さなど）は、規格に寸法の規定がないため、規格の図に合わせた近似です。

## 書き方の規則

- 1行は、`キーワード 文字`の形です。キーワードは、英語の小文字だけです。
- 図記号の中の文字は、キーワードの後ろの、残り全部です。長いと、図記号の中で、自動で折り返します。
- 文字の中で改行したいときは、`\n`と書きます。
- 空の行と、`//`で始まる行は、無視します（注釈）。
- 字下げは、半角の空白だけです。タブは使えません。1段は、空白2つを勧めます。同じ文書の中で、そろえてください。

### キーワードで始まる処理の文

キーワードのない行は、処理です。ただし、処理の文が、たまたまキーワード（`data`・`end`など）で始まると、その図記号になります。次のどちらかで避けます。

- `process`を付けます: `process data cleanup を実行する`
- 文を`"`でくくります: `"data cleanup を実行する"`。行頭が`"`の行は、処理です。

```text
"data cleanup を実行する"
process end user に通知する
data "end of file を確認"
```

```flowchart
"data cleanup を実行する"
process end user に通知する
data "end of file を確認"
```

`"`でくくった文字の中で、`"`を書くときは、`\"`と書きます。閉じ忘れは、誤りです。

## 分岐

`judge`の次の行から、1段深く字下げして、分岐を書きます。分岐は、`ラベル:`で始めます。ラベルは、自由な文字です（`はい`・`いいえ`・`承認`・`却下`など）。矢印のそばに出ます。

```text
judge 在庫がある?
  はい:
    出荷する
    data 出荷通知を表示
  いいえ: 取り寄せる
請求書を作る
```

```flowchart
judge 在庫がある?
  はい:
    出荷する
    data 出荷通知を表示
  いいえ: 取り寄せる
請求書を作る
```

- `ラベル:`の後ろに、図記号を続けて書けます（1つだけ）。次の行以降を、さらに深く字下げして、続けてもかまいません。
- 分岐は、2つ以上です。3つ以上も書けます。1つだけの`judge`は、誤りです。
- 全部の分岐は、次の行（`judge`と同じ深さ）で、合流します。合流のための記号は、描きません。
- 空の分岐（`ラベル:`だけ）は、`judge`から、直接、次の図記号へ進みます。
- 分岐の最後が`end`なら、その分岐は、合流しません。

```text
start
judge 承認?
  はい: 続ける
  却下: end 却下
次の処理
end
```

```flowchart
start
judge 承認?
  はい: 続ける
  却下: end 却下
次の処理
end
```

分岐の中に、`judge`や繰り返しを、入れ子にして書けます。

```flowchart
judge 在庫がある?
  はい:
    judge 数量は足りる?
      はい: 全部出荷
      いいえ: 一部出荷
  いいえ: 取り寄せる
請求書を作る
```

## 繰り返し

`loop 名前: 条件`から`endloop`までを、ループ端の対にします。間は、1段深く字下げします。

```text
loop 注文処理: 注文がなくなるまで
  注文を1件処理する
endloop
```

```flowchart
loop 注文処理: 注文がなくなるまで
  注文を1件処理する
endloop
```

規格は、ループ端を「二つの部分からなり、ループの始まりと終わりを表す。記号の二つの部分は、同じ名前をもつ」と定めています。初期化・増分・終了条件は、テストの位置に応じて、始端か終端の、どちらか一方に書きます。

- **名前**は必須です。始端と終端の、両方の記号に、同じ名前が出ます。終端の名前は、`endloop`が、始端から引き継ぎます。
- **条件**は、`:`の後ろに書きます。省略できます。
- 条件は、始端か終端の、どちらか一方にだけ書けます。始端に書くときは`loop 名前: 条件`、終端に書くときは`endloop: 条件`です。両方に書くと、誤りです。
- 戻る矢印は、描きません。始端と終端の対が、間を繰り返すことを表します。

条件を終端に書くと（先に処理をして、あとで続けるかを調べる繰り返しです）、条件が、下のループ端に出ます。

```text
loop 入力待ち
  data 入力を受ける
endloop: 入力が正しいまで
```

```flowchart
loop 入力待ち
  data 入力を受ける
endloop: 入力が正しいまで
```

繰り返しは、入れ子にできます。外側と同じ名前は、使えません（対応が、あいまいになるため）。分岐の中にも書けます。

```flowchart
loop 注文処理: 注文がなくなるまで
  data 注文を入力
  loop 再試行
    在庫を確認する
  endloop: 在庫があるまで
  出荷する
endloop
```

## 線の引き方

線は、水平と垂直だけで引きます。

- 判断の出口は、ひし形の左右の頂点、または下の頂点から出ます。3つの分岐は、左・下・右になります。
- 次の記号に入る線が2本以上のときは、記号の少し上で、水平にまとめて、1本にして入ります。矢じりは、入るところに1つだけ付きます。
- 前後の記号の中心は、縦にそろいます。

```flowchart
judge 区分は?
  A: 処理A
  B: 処理B
  C: 処理C
集計する
```

流れの向きは、上から下です。向きを変える指定は、まだありません。

## 誤り

構文の誤りがあると、ビルドは失敗し、原稿の行つきで、原因を示します（メッセージは、英語です）。

| 誤り | メッセージの例 |
|---|---|
| 分岐が1つだけの`judge` | `A judge needs at least two branches.` |
| `loop`に対応する`endloop`がない | `The loop 'L' has no matching endloop.` |
| 条件を、始端と終端の両方に書いた | `A loop condition goes at either the start or the end, not both.` |
| 字下げにタブを使った | `Tabs are not allowed in indentation; use spaces.` |
| `"`の閉じ忘れ | `Unclosed quote.` |

## 設定と、使える場所

- `plugins.flowchart`（既定`true`）を`false`にすると、` ```flowchart `フェンスを描かず、素のコード表示にします（「プラグインと入力」の章を参照）。
- 図の大きさは、他の図と同じく、フェンス属性（`{width=60%}`）で指定できます。
- `.flow`ファイルも、`chapters`に指定できます（1ファイル＝1章）。
- PDF出力でも、Obunzuでも、同じ図になります。Obunzuでは、`.flow`を、単体のファイルとして開けます。

## まだできないこと

- ラベルへ飛ぶ書き方（`goto`型）と、番号付きの表の書き方。
- 向きの指定（左から右）、サブグラフ（まとまり）、スイムレーン（担当ごとの帯）。
- 色・線の太さなどの、個別の装飾。図記号の見た目は、文書にそろえて、固定しています。
- 規格にある、手作業・手操作入力・表示・結合子などの記号。

この記法は、JIS X 0121に準じた、非公式の実装です。規格そのものの代わりにはなりません。規格を確かめたいときは、JIS X 0121（情報処理用流れ図・プログラム網図・システム資源図記号）の本文を、ご覧ください。
