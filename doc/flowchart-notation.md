# フローチャートの記法（`flowchart`フェンス）の設計（[#536](https://github.com/tokudiro/text-compositor/issues/536)）

JIS X 0121（情報処理用流れ図・プログラム網図・システム資源図記号。ISO 5807と対応）の図記号に準じてフローチャートを描くための、独自の記法を定める。Mermaidの`flowchart`の記法は変えない。Mermaidの`flowchart`は、従来どおり、```` ```mermaid ````で書き、ブラウザ版のMermaidが描く。

> **規格の本文と照合した（2026-10-25）。** JIS X 0121:1986の本文は、[kikakurui.com](https://kikakurui.com/x0/X0121-1986-01.html)で公開されている。図記号の形と用語を、本文・図と突き合わせた。結果は、5.2に記す。

## 1. 位置づけ

### 1.1 経緯

* [#532](https://github.com/tokudiro/text-compositor/issues/532)で、Mermaidのflowchartを自作の変換器で描く試作を作った。配置は、Graphvizの`dot`（Typstのパッケージ`diagraph-layout`）で求め、SVGは自分で描く。矢印の交差が少なく、配色・折り返し・矢印のラベルの背景を、文書に合わせられることを確かめた。
* 一方、Mermaidの記法（`[ ]`・`{ }`など）では、ループ端・書類などの図記号を書けない。JIS X 0121に準じるには、記法から作り直す必要がある。
* そこで、Mermaidの代わりのプラグインは作らず、自作の変換器を、新しい記法のために使う（2026-10-22に決定）。

### 1.2 方針

* **Mermaidの記法は、変えない。** 既存の原稿は、そのまま動く。
* **新しいフェンス`flowchart`を足す。** PDF・HTML（Obunzu）で、同じSVGを使う。
* **書きやすさを、優先する。** このツールの主な用途は、LLMが書いたMarkdownをPDFにすることである。上から下へ、疑似コードのように読める、字下げの記法にする。
* **飛び先が自由な図は、後回しにする。** 順次・分岐・繰り返しは、記法で表せる。ラベルへ飛ぶ書き方（`goto`型）と、番号付きの表の書き方は、必要になってから足す。足しても、書いた図は、そのまま動く（6章）。

## 2. 記法

### 2.1 例

```text
start
loop 10回まで
  data 金額を入力
  消費税を計算する
  judge 1万円以上?
    はい: 送料を無料にする
    いいえ: 送料を加算する
  data 合計を表示
endloop
end
```

### 2.2 図記号とキーワード

1行に、図記号を1つ書く。行の形は、`キーワード 文字`である。**キーワードは英語だけ**で、日本語の別名は設けない（書き方を1通りに絞るため）。

**キーワードを書かない行は、処理になる。** フローチャートの行の大半は処理であり、毎回`process`と書くのは冗長だからである。処理の文が、たまたまキーワードで始まるときは、次のどちらかで避ける。

* `process`を明示する（例: `process data cleanup を実行する`）。
* 文を`"`でくくる（例: `"data cleanup を実行する"`）。行頭が`"`の行は、キーワードなしの処理である。

| キーワード | 図記号（JIS X 0121） | 形 | 備考 |
| --- | --- | --- | --- |
| `start`・`end`・`terminal` | 端子 | 角丸の長円 | `start`・`end`は、文字を省ける（その言葉を表示する） |
| （なし）・`process` | 処理 | 長方形 | キーワードなしの行は、処理 |
| `judge` | 判断 | ひし形 | 分岐を、続けて書く（2.4） |
| `data` | データ（入力・出力） | 平行四辺形 | 入力にも出力にも使う（規格どおり） |
| `sub` | 定義済み処理 | 左右に縦線のある長方形 | |
| `prep` | 準備 | 六角形 | 初期値の設定など。**ループ端ではない** |
| `loop`〜`endloop` | ループ端（始まりと終わり） | 上（または下）の2つの角を落とした長方形 | 対で使う（2.5） |
| `doc` | 書類 | 下の辺が波線の長方形 | |

* 形は、規格の図（8章）と照合済み。大きさの比率（角を落とす大きさ、波線の高さなど）は、規格に寸法の規定がない。図に合わせて、描いた結果を比べて直す。
* 規格は、記号の角度を変えてはならず、左右反転は使わない方がよい、と定める（9.1(2)）。
* 規格には、ほかにも記号がある（手操作入力・表示・結合・照合など）。必要になってから足す。

### 2.3 文字

* キーワードは、行頭の1語（英小文字）で、後ろに空白が続くものだけを指す。それ以外の行は、処理の文である。
* 図記号の中の文字は、行の、キーワードの後ろの、残り全部である。前後の空白は、除く。
* 文字は、`"`でくくってもよい（キーワードの後ろでも使える。例: `judge "end of file?"`）。くくった中の`"`は`\"`と書く。閉じ忘れは、その行の誤りである。
* 長い文字は、図記号の中で、自動で折り返す（日本語は、文字の間。カタカナ・英数字の続きは、1語として扱う）。
* 明示の改行は、`\n`と書く。
* 空の行と、`//`で始まる行は、無視する（注釈）。

### 2.4 分岐

`judge`の次の行から、**1段深く字下げして**、分岐を書く。分岐は、`ラベル:`で始める。

```text
judge 在庫がある?
  はい:
    出荷する
    data 出荷通知を表示
  いいえ: 取り寄せる
請求書を作る
```

* 分岐のラベルは、矢印のそばに、文字として出す。ラベルは、自由な文字（`はい`・`いいえ`・`承認`・`却下`など）。
* `ラベル:`の後ろに、図記号を続けて書ける（1つだけ）。次の行以降を、さらに深く字下げして、続けてもよい。
* 分岐は、2つ以上。1つだけの`judge`は、誤りである。
* 全部の分岐は、**次の行（judgeと同じ深さ）で、合流する。** 合流のための記号は、描かない（矢印を、合わせる）。
* 分岐の最後が`end`なら、その分岐は、合流しない。
* 空の分岐（`ラベル:`だけ）は、judgeから、直接、次の図記号へ、矢印が出る。

### 2.5 繰り返し

`loop 名前: 条件`から`endloop`までを、**ループ端の対**にする。間は、1段深く字下げする。

```text
loop 注文処理: 注文がなくなるまで
  注文を1件処理する
endloop
```

規格（JIS X 0121 8.2.2(6)）は、ループ端を「二つの部分からなり、ループの始まりと終わりを表す。記号の二つの部分は、同じ名前をもつ」と定める。初期化・増分・終了条件は、**テスト命令の位置に応じて、始端または終端の、どちらか一方**に書く。

* **名前**は必須。始端と終端の、両方の記号に、同じ名前を出す。終端の名前は、`endloop`が、始端から引き継ぐ。
* **条件**は任意。`:`の後ろに書く。書かなければ、名前だけを出す。
* 条件は、始端か終端の、**どちらか一方**にだけ書ける。始端に書くときは`loop 名前: 条件`、終端に書くときは`endloop: 条件`（後判定）。両方に書くのは、誤りである。
* 始端に条件がある場合は、「条件が成立したとき、同じ名前の終端へ飛ぶ」ことを表す（規格の備考2）。
* **戻る矢印は、描かない。** 規格のループ端は、始端と終端を対にして、間を繰り返すことを表す。
* 繰り返しは、入れ子にできる。分岐の中にも、書ける。入れ子の名前は、外側と重ねない（対応が、あいまいになるため）。
* `loop`と`endloop`の数が合わないのは、誤りである。

### 2.6 字下げと全体

* 字下げは、**空白（半角）だけ**。タブは、誤りである。1段は、空白2つを勧める。同じ文書の中では、一貫させる（1段の幅は、最初の字下げから決める）。
* 全体は、**上から下へ**流れる。向きを変える指定は、いまは設けない（6章）。
* 最初の行は、`start`（または`terminal`）を勧める。`start`と`end`が、なくてもよい（誤りにしない）。

### 2.7 規則のまとめ（文法）

```text
図        := 行*
行        := 字下げ (図記号行 | 分岐行 | 繰り返し行 | 繰り返し終了行)
図記号行  := [キーワード] [文字]         ※キーワードなしは処理。judgeは、続けて分岐行を書く
分岐行    := ラベル ":" [図記号行]
繰り返し行:= "loop" 名前 [":" 条件]
繰り返し終了行 := "endloop" [":" 条件]   ※条件は、loopとendloopの一方だけ
```

## 3. 解析と内部の形

* 解析は、字下げと行頭のキーワードを読む、小さな手書きの解析器である。**文脈を持たない**（1行ごとに、キーワードで判別できる。キーワードがなければ処理）。
* 解析の結果は、**箱（ノード）と矢印（エッジ）**の並びである。[#532](https://github.com/tokudiro/text-compositor/issues/532)の試作（`flowchart_render.py`）の`Flowchart`と同じ形にする。そのため、配置（`dot`）と、SVGの描画は、そのまま使える。
* 新しい形（ループ端の上下・書類）は、描画に足す。
* 矢印の、ラベル（分岐の文字）は、`dot`の配置が、場所を空ける。

## 4. 登録と接続

* フェンスは、`flowchart`。章ファイルの拡張子は、`.flow`（案）。
* 登録簿（[#533](https://github.com/tokudiro/text-compositor/issues/533)。`doc/plugin-architecture.md`）の、1つのプラグイン`flowchart`として載せる。バックエンドは、自作の変換器（`native`）1つで、出力は`svg`。**従来のブラウザ版へ戻す分岐（フォールバック）は、ない**（独自の記法のため、ほかの描き手がない）。
* `plugins.flowchart`（既定`true`）で、無効にできる。無効なら、素のコード表示にする。
* キャッシュは、他のSVGの図と同じ（`flowchart`・版・コードのハッシュ）。版は、変換器・`diagraph-layout`・Typst・フォントの版を含める。
* 診断（誤りの行）は、原稿の行にそろえて、報告する（仕様9章のFail-fast）。

## 5. 見送るもの・確かめるもの

### 5.1 いまは扱わない

* ラベルへ飛ぶ書き方（`goto`型）、番号付きの表の書き方。
* 向きの指定（左から右）、サブグラフ（まとまり）、スイムレーン（担当ごとの帯）。
* 色・線の太さなどの、個別の装飾。図記号の見た目は、文書にそろえて、固定する。
* リンク、アニメーション。

### 5.2 規格との照合（2026-10-25）

JIS X 0121:1986の本文と図で、次のとおり確かめた。

* **図記号の形:** 端子（長円）・処理（長方形）・判断（ひし形）・データ（平行四辺形）・定義済み処理（左右に縦線のある長方形）・準備（六角形）・書類（下辺が波線の長方形）は、設計書のとおり。
* **ループ端:** 2つの角を落とした長方形。始端は上の角、終端は下の角を落とす（短辺が上、長辺が下）。始端と終端は同じ名前をもち、条件は、どちらか一方に書く。これに合わせて、2.5を直した。
* **用語:** 「端子」「データ」「準備」「ループ端」は、規格の用語のとおり。
* **分岐のラベル:** 規格は、判断の各出口に、条件を、線に近接して書くと定める（9.3.1(2)）。2.4のとおり。
* **流れ線:** 標準の向きは、左から右・上から下。線は、記号の左か上から入り、右か下から出る。延長線は、記号の中心を通る。合流する線は、ずらす。交差は、避けた方がよい（9.2.1）。配置と描画の段階で、合わせる。

**未確定:** 大きさの比率（角を落とす大きさ、波線の高さ、ひし形の縦横比）。規格に寸法の規定はない。図を見て決め、描いた結果で調整する。

**まだ扱わない記号（規格にある）:** 並列処理・手作業・手操作入力・表示・結合子・注釈・省略など（6章）。

## 6. 拡張の余地

後から足しても、書いた図が、そのまま動くように、いまの記法は、決めている。

* **ラベルへ飛ぶ書き方**: `ラベル 名前`で、位置に名前を付け、`へ 名前`で、そこへ矢印を引く。分岐の中や、後ろから、前の位置へ戻るときに使う。
* **向きの指定**: フェンスの属性（例: `{direction=lr}`）。
* **ほかの図記号**: 手操作入力・表示・結合などを、キーワードで足す。

## 7. 実装の順序

1. 解析（字下げ・キーワード・分岐・繰り返し・誤りの行）と、そのテスト。
2. 描画に、ループ端・書類の形を足す。
3. 登録簿に載せる（フェンス・章ファイル・`plugins.flowchart`・キャッシュ）。
4. 使い方ガイドに、フローチャート専用のガイドを書く（記法の説明と、処理・入力・判断・繰り返しの例）。Mermaidのギャラリー（`14_gallery_mermaid.md`）には、足さない（Mermaidの記法ではないため）。
5. 仕様書に、書く。

各ステップは、独立したPRにする。
