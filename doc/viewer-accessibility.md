# Obunzu Markdown Viewerの、アクセシビリティ（#340）

Obunzu Markdown Viewerの画面（ツールバー・検索・設定画面・エラーの帯・表示中の文書）の、スクリーンリーダーとキーボードでの使いやすさに関する、調査の結果と、対応の範囲、確認の方法を記す。PDF出力のアクセシビリティ（PDF/UAなど）は、別の話で、[#319](https://github.com/tokudiro/text-compositor/issues/319)で扱う。

## 調査の結果（2026-10-02）

axe-core 4.13（`viewer/scripts/check-a11y.js`）と、実際のElectronの操作で、調べた。

**すでに、できていたこと**
- ツールバーのアイコンのボタンは、`aria-label`を持ち、キーボードのフォーカスの枠（`:focus-visible`）も、見える。
- オンオフの切り替えは、`role="switch"`と`aria-checked`、押している状態の切り替えは、`aria-pressed`を持つ。
- 設定の選択肢は、`role="radiogroup"`と、見出しの`aria-labelledby`を持ち、矢印キーで選べる。入力そのものは、画面に見えないが、フォーカスできる。
- 検索の件数は、`aria-live="polite"`で、読み上げられる。
- 主な操作には、すべて、ショートカットキーがある（`Ctrl+O`・`Ctrl+F`・`Ctrl+,`・`F5`・`Alt+←`・`Ctrl+±`など）。

**問題だったこと**

| 項目 | 内容 | 重大度（axeの判定） |
| --- | --- | --- |
| 文書の言語 | 変換したHTMLの`<html>`に、`lang`が無い。スクリーンリーダーが、読み上げの言語（日本語・英語）を決められない | serious |
| 文字のコントラスト比（ライト） | 設定で、選んでいる選択肢の文字が、`#0078d4`と`#dcebf8`で、3.7:1。基準（4.5:1）に足りない | serious |
| 文字のコントラスト比（ダーク） | 同じ組み合わせが、4.1:1。足りない（自動のチェックは、ダークを調べていなかったため、実測して分かった） | serious |
| 画面の構造 | ツールバー・検索・帯が、ランドマークに入っていない。ツールバーに、`role="toolbar"`が無い | moderate |
| エラー・警告の通知 | エラーの帯が出ても、スクリーンリーダーに、通知されない（`aria-live`・`role="alert"`が無い）。変換中・更新の完了も、同じ | （axeでは検出されない） |
| 帯の「詳細」 | `<span>`で、キーボードで押せない。開いているか閉じているかも、伝わらない | （axeでは検出されない） |
| ツールバーへの到達 | ツールバーと文書は、別のビューで、`Tab`では行き来できない。ショートカットのない操作（拡大率のボタンなど）に、キーボードだけで届かない | （axeでは検出されない） |
| 設定画面のフォーカス | 設定を開いても、フォーカスが、設定の中へ移らない | （axeでは検出されない） |
| 拡大率のボタン | 名前が「実寸に戻す」だけで、今の倍率が、伝わらない | （axeでは検出されない） |
| 動き | 変換中の帯の動きが、「動きを減らす」設定に従わない | — |

## 対応の範囲

**全面対応にした。** 見つかった問題のうち、画面の部品の側で直せるものは、すべて直した。

- **文書のHTML**: `<html lang>`を出す。front-matterの`lang`（例: `lang: en`）があれば、それ。無ければ、本文に、かな・漢字があるとき`ja`、なければ`en`。
- **ウィンドウ本体のビュー**: `<html lang="ja">`・`<header>`のランドマーク・`role="toolbar"`（名前つき）・`role="search"`・`<main>`（何も開いていないときの案内）。
- **通知**:
  - エラーの帯は`role="alert"`（すぐ読み上げ）、警告の帯は`role="status"`（今の読み上げを遮らない）。同じ文字で、要素の中身を置き換えないようにして、同じ内容を、読み直させない。
  - 読み上げ専用の領域`#live`（`role="status"`）に、「変換中」と、更新の完了を出す。画面の`#busy`・`#status`は、`aria-hidden`にして、二重に読ませない。
- **キーボード**:
  - 帯の「詳細」は、ボタン（`aria-expanded`・`aria-controls`つき）。
  - **`F6`で、ツールバーと文書の間を、行き来できる**（「表示」メニューにもある）。
  - 設定を開くと、フォーカスが、見出し「設定」へ移る。閉じると、文書へ戻る（文書が無いときは、歯車のボタンへ）。
- **名前**: 拡大率のボタンは、「実寸に戻す（現在 100%）」。
- **配色**: 文字に使うアクセント色を、`--accent-text`に分けた（ライト`#005a9e`で5.9:1、ダーク`#7ab8f0`で5.5:1）。選択中の選択肢・トグルのボタン・行番号に使う。
- **動き**: `prefers-reduced-motion`のとき、変換中の帯の動きを止める。

- **図の代替テキスト**: フェンスの属性`{alt="..."}`で、原稿に書けるようにした（[#398](https://github.com/tokudiro/text-compositor/issues/398)。書き方は、図表の章の「代替テキスト（alt）」）。書かなかった図は、これまでどおり、`mermaid diagram`のように、種類だけ。

**対応しないこと（理由つき）**
- スクリーンリーダー（NVDAなど）での、実際の読み上げの確認。自動では確かめられないため、下の手順で、手動で確認する。

## 確認の方法

### 自動

```bash
cd viewer
TEXT_COMPOSITOR_PYTHON=<python.exeのパス> TEXT_COMPOSITOR_PYTHONPATH=<リポジトリ> node scripts/check-a11y.js
```

実際のElectronを起動して、次を確かめる（Windowsのみ。実行中は、ほかのウィンドウを操作しないこと）。

- axe-coreの違反が無い。ツールバー・検索・設定画面・エラーの帯と一覧・文書の表示。ライトとダークの両方（コントラスト比を含む）。ウィンドウ本体のビューは、見出しも、メインのランドマークも持たない（文書は、別のビュー）ため、`landmark-one-main`と`page-has-heading-one`だけは、調べない。
- ランドマーク・名前・役割・状態（上の「対応の範囲」のとおり）。
- 設定を開いたときのフォーカス。`F6`での行き来（実際のキー操作）。

文書の表示は、DevTools Protocolから直接は調べられないため、変換済みのHTMLを、別のウィンドウで開いて、調べる（`viewer/scripts/a11y-content.js`）。axe-coreは、開発用の依存（MPL-2.0）で、配布物には入らない。

### 手動（NVDA）

自動では、読み上げの実際を、確かめられない。リリースの前などに、次を確認する。

1. NVDAを起動して、Obunzuを開く。
2. 文書を開いて、`F6`でツールバーへ移り、`Tab`で、各ボタンの名前と状態が、読み上げられる（「再読み込み」「保存したら自動で更新、オン」「実寸に戻す（現在 100%）」など）。
3. `F6`で、文書へ戻り、見出しの一覧（NVDAの要素リスト）で、見出しの階層が出る。
4. 壊れた図を含む文書を開き、エラーが、自動で読み上げられる（「変換エラー…」）。
5. `Ctrl+,`で設定を開き、「設定」と読まれ、`Tab`で、各項目の名前と選択肢の状態が読まれる。
