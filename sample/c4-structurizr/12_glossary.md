# 12 用語集

この文書で使う、業務と技術の用語を、五十音順（英字を先頭）に示す。文書の中で、同じ意味で使う。業務の用語が出るページは、巻末の用語索引で引ける。

| 用語 | 定義 | 参照 |
| --- | --- | --- |
| ADR | 設計の判断を、状況・代替案・決定・結果で記録したもの。Architecture Decision Recordの略 | 9章 |
| ASR | アーキテクチャ上、特に重要な要求。この文書では、品質目標Q1〜Q4と、評価のシナリオS1〜S4。Architecturally Significant Requirementsの略 | 1.5、10章 |
| C4モデル | ソフトウェアの構造を、System Context・Container・Component・Codeの階層で描く方法 | 1.1 |
| 受付（`PENDING`） | 在庫を引き当て、決済の結果を待っている、注文の状態 | 5.5 |
| 打切り | 外部の呼び出しを、決めた時間で、待つのをやめること。決済は3秒 | ADR-2、8.3 |
| 運用担当 | ECサイトの商品・在庫の管理と、出荷指示、障害への対応を行う人。1人。ロールは`OPERATOR` | 1.6、8.1 |
| 外形監視 | サイトの外から、定期的にアクセスして、稼働を確かめる監視 | 7.4 |
| 確定（`CONFIRMED`） | 在庫を引き当て、決済が成功した、注文の状態 | 5.5 |
| カート | 利用者が、注文する商品を、一時的に入れておく場所 | F1・F2 |
| 決済ID | 決済代行サービスが、決済ごとに付ける識別子。注文に保存する | 8.5 |
| 決済代行サービス | カード決済を処理する外部のサービス。カード情報は、このサービスだけが受け取る | 3章、ADR-4 |
| 決済トークン | 決済代行サービスの画面で、カード情報を入力した結果として、利用者に渡される、決済用の使い捨ての値。カード番号の代わりに使う | ADR-4 |
| 在庫の引き当て | 注文された数量を、在庫から確保すること。条件付きの更新で行う | 5.6、ADR-3 |
| 在庫の戻し | 引き当てた在庫を、元に戻すこと。取消や決済の失敗のときに行う | 5.6 |
| 出荷指示 | 確定した注文を、倉庫に出荷させる指示。CSVで出力する | F5、5.4 |
| 照合 | 取り消された注文と、決済代行サービスの記録を、突き合わせること。毎日午前3時 | 5.10、6.5 |
| セール期間 | 年2回、各約1週間のセール。注文が最大30件/分になる。年間の売上の4割を占める | 1.3 |
| 取消（`CANCELLED`） | 決済の失敗、利用者の取消、障害で、取り消された、注文の状態 | 5.5 |
| 評価のシナリオ | 品質目標を、測れる形にした状況と目標値。S1〜S4 | 10章 |
| 品質目標 | アーキテクチャ上、特に重要な品質。Q1性能効率・Q2可用性・Q3変更容易性・Q4セキュリティ | 1.5 |
| 冪等 | 同じ操作を何回行っても、結果が同じになること。`cancel`は、取消済みなら何もしない | 5.5 |
| ヘルスチェック | コンテナが、正常に動いているかを、定期的に確かめる仕組み | 7.3 |
| 利用者 | ECサイトで、商品を探して注文する人。ロールは`CUSTOMER` | 1.6、8.1 |
