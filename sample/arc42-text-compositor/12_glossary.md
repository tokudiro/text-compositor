# 12 用語集

この文書で使う用語を、五十音順（英字を先頭）に示す。文書の中で、同じ意味で使う。本文で、二重の角括弧をつけた用語が出るページは、巻末の用語索引で引ける。

| 用語 | 定義 | 参照 |
| --- | --- | --- |
| ADR | 設計の判断を、状況・代替案・決定・結果で記録したもの。Architecture Decision Recordの略 | 9章 |
| ASR | アーキテクチャ上、特に重要な要求。この文書では、品質目標Q1〜Q5と、評価のシナリオS1〜S5 | 1.5、10章 |
| arc42 | アーキテクチャ設計書の章立てのテンプレート。12章ある | 1.1 |
| C4モデル | ソフトウェアの構造を、System Context・Container・Component・Codeの階層で描く方法 | 1.1 |
| Fail-fast | 失敗したら、静かに続けず、早く、診断つきで止まること | ADR-7、8.4 |
| Obunzu | Obunzu Markdown Viewer。Markdownを開いて、HTMLで表示する、閲覧専用のViewer。Electron製 | 5.1、7.4 |
| Typst | 組版のための言語と、そのコンパイラ。この文書の組版エンジン | ADR-1 |
| 原稿 | 書き手が書く、Markdown・図表のソース・CSVなどのファイル。見た目は、持たない | 1.2 |
| 決定論的出力 | 同じ入力から、同じ出力が得られること。版の固定とキャッシュのキーで保つ | 8.1、ADR-1 |
| 書き手 | 原稿と設定を書く人。人、または、人が仕上げるAI | 1.6 |
| 常駐ワーカー | `python -m text_compositor.worker`。Viewerのために、変換エンジンを常駐させ、文書ごとに監視と再変換をする | 5.6、ADR-5 |
| 診断 | 警告・エラー・ヒント・情報。原稿の行（分かる場合）つき | 8.3 |
| 同梱 | 配布物の中に、あらかじめ入れておくこと。Obunzuのzipでは、Python・Java・各図表ツールなどを同梱する | 7.4、ADR-6 |
| フェンス | Markdownの、```` ``` ````で囲んだブロック。言語名（`plantuml`など）で、描き方が決まる | 1.4 |
