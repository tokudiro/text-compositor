# 3 コンテキストとスコープ

ECサイトの外側にいる人と、外部のシステムとの関係を示す。業務上の関係と、技術的な関係に分けて書く。

## 3.1 業務上のコンテキスト

```plantuml
@startuml
!include <C4/C4_Context>
!include c4-defs.iuml
LAYOUT_LEFT_RIGHT()

Person(customer, $customer_name, $customer_desc)
Person(operator, $operator_name, $operator_desc)
System(ec, $ec_name, $ec_desc)
System_Ext(pay, $pay_name, $pay_desc)
System_Ext(mail, $mail_name, $mail_desc)
System_Ext(logistics, $logistics_name, $logistics_desc)

Rel(customer, ec, "商品を探して、注文する")
Rel(operator, ec, "商品と在庫を管理し、出荷指示を出力する")
Rel(ec, pay, "決済と返金を依頼する")
Rel(ec, mail, "メールの送信を依頼する")
Rel(operator, logistics, "出荷指示のCSVを渡す")
Rel(operator, pay, "管理画面で返金する")
Rel(mail, customer, "確認・取消のメールを送る")
Rel(mail, operator, "通知のメールを送る")
@enduml
```

<!-- pagebreak -->

| 相手 | やり取りする内容 | 備考 |
| --- | --- | --- |
| [[利用者]] | 商品の閲覧、注文、注文履歴の確認、注文の取消（F1・F2・F3） | スマートフォンからの利用が、約7割（TC5） |
| [[運用担当]] | 商品と在庫の管理、[[出荷指示]]の出力、障害の通知の受け取り（F4・F5） | 1人。二要素認証でログインする（8.1） |
| [[決済代行サービス]] | 決済と返金の依頼。夜間の[[照合]]のための、決済の記録の取得 | 契約済み。カード情報は、このサービスだけが受け取る（TC2、ADR-4）。仕様変更は、3か月前に通知される（OC5）。[[打切り]]後の食い違いの返金は、運用担当が、この管理画面で行う（6.5） |
| メール配信サービス | 注文の確認・取消のメールを利用者へ、食い違いや障害の通知のメールを運用担当へ、送る | 送信の失敗は、注文の確定に影響させない（8.3） |
| 物流倉庫 | 出荷指示のCSVを受け取り、出荷する | ECサイトとは、つながらない。運用担当が、CSVを手で渡す（1.2。連携は対象外） |

## 3.2 技術的なコンテキスト

| やり取り | 向き | チャネル | 形式・決まり |
| --- | --- | --- | --- |
| 利用者・運用担当のブラウザとECサイト | ブラウザ → ECサイト | HTTPS（TLS 1.2以上） | 画面はHTML。データの取得と更新は、REST（JSON）。対応ブラウザは、2.1のTC5 |
| 決済と返金の依頼 | ECサイト → 決済代行サービス | HTTPS（TLS 1.2以上） | 決済代行サービスが定めるREST（JSON）。呼び出しは3秒で打ち切る（ADR-2）。送るのは、トークンと金額だけ（ADR-4） |
| 決済の記録の取得 | ECサイト → 決済代行サービス | HTTPS | 前日分を、1日1回（午前3時）取得する（6.5） |
| メールの送信の依頼 | ECサイト → メール配信サービス | SMTP（TLS） | 5秒で打ち切る。5分間隔で、最大3回、再試行する（8.3） |
| 出荷指示の受け渡し | 運用担当 → 物流倉庫 | （システム外） | CSV（UTF-8）。列は、注文ID・配送先・商品ID・数量（6.6） |

- 決済代行サービスと、メール配信サービスの、どちらが止まっても、ECサイトの他の機能（商品の閲覧など）は、動き続ける。
- ECサイトが、自分から呼び出す外部サービスは、決済代行サービスと、メール配信サービスの2つだけである。
