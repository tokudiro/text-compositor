## 1.2 目的とスコープ

**目的**: 小規模なブランドが、自社のECサイトを、少ない人数で運営し、育てられるようにする。具体的には、商品の掲載、注文の受付、在庫の管理、決済、[[出荷指示]]までを、1つのシステムで行う。

**対象（スコープ内）**
- [[利用者]]向けの、商品の閲覧・カート・注文・注文履歴の確認
- 運用担当向けの、商品登録・在庫更新・注文の確認と出荷指示
- [[決済代行サービス]]（外部）との連携と、メール配信サービス（外部）への通知の依頼

**対象外**
- 会員ポイント、クーポン、レビュー（将来の拡張とし、今回は設計しない）
- 物流倉庫のシステムとの連携（出荷指示は、CSVを出力するところまで）
- 海外向けの販売（通貨は円のみ、配送先は国内のみ）

## 1.3 前提

この設計は、次の事業上の前提に基づく。前提が変わったときは、設計を見直す。

| 項目 | 前提 |
| --- | --- |
| 商品点数 | 約3,000点 |
| 注文数 | 1日平均200件。[[セール期間]]は、最大で30件/分 |
| 利用者数 | 同時に閲覧する人数は、通常50人、セール期間は500人 |
| 体制 | 開発者3人、運用担当1人 |
| 決済 | 既存の決済代行サービスと契約済み。カード番号は、自社のシステムに保存しない |

## 1.4 要求の概要

主な機能は次のとおり。

| 番号 | 機能 | 説明 |
| --- | --- | --- |
| F1 | 商品の閲覧 | 商品の一覧・検索・詳細を表示する |
| F2 | 注文 | カートに入れた商品を、在庫を確認して注文し、決済する |
| F3 | 注文履歴 | 利用者が、自分の注文の状態を確認する |
| F4 | 商品・在庫の管理 | 運用担当が、商品の登録と、在庫の更新を行う |
| F5 | 出荷指示 | 運用担当が、確定した注文の出荷指示（CSV）を出力する |
| F6 | 通知 | 注文の確定と出荷のときに、利用者へメールを送る |

## 1.5 品質目標

アーキテクチャ上、特に重要な品質目標は、次の4つ。数値の目標は、10章に書く。

| 番号 | 品質 | 動機 |
| --- | --- | --- |
| Q1 | 性能効率 | 注文の確定が遅いと、利用者がカートを離れる。セール期間の売上が、年間の4割を占めるため、ピーク時にも、注文確定の待ち時間を保つ必要がある |
| Q2 | 可用性 | 運用担当が1人のため、夜間・休日に、すぐに対応できない。サーバーの障害が、自動で回復し、注文を取りこぼさない構成にする |
| Q3 | 変更容易性 | 決済手段（コード決済など）の追加要望が、年に1〜2回ある。少人数でも、短い期間で追加できる構成にする |
| Q4 | セキュリティ | カード情報の漏えいは、事業を続けられなくなる損害になる。カード番号を保存しない構成にして、守る対象を減らす |

## 1.6 関係者

| 役割 | 関心事 |
| --- | --- |
| 利用者（顧客） | 商品を探して、迷わず注文できること。注文の状態が分かること |
| 運用担当 | 在庫と注文を、少ない手間で管理できること。障害を早く知り、直せること |
| 開発者 | 変更の影響が分かりやすく、少人数でも保守できること |
| 事業責任者 | 売上の機会を逃さないこと。費用が、予算の範囲に収まること |
| 決済代行サービス（外部） | 決まった方式（HTTPS）で、正しく依頼されること |

## 1.7 このサンプルの書き方（PlantUML版）

この文書の図は、PlantUMLの標準ライブラリに入っている、C4-PlantUML（<https://github.com/plantuml-stdlib/C4-PlantUML>）のマクロ（`Person`・`Container`・`Rel`など）で書く。ライブラリは、`plantuml.jar`に同梱されているため、`!include <C4/C4_Container>`と書くだけで使える。追加の取得は要らない。

同じ題材を、Structurizr DSLで書いた例が、`sample/c4-structurizr/`にある。

| | Structurizr（`sample/c4-structurizr/`） | PlantUML（この例） |
| --- | --- | --- |
| 追加で要るもの | `plugins.structurizr: true`、Java、`structurizr-cli`（約99MB） | なし（既定で使える。Javaは、無ければ自動で取得する） |
| モデルの共有 | 1つのモデルを、すべてのビューが共有する | 図ごとに、要素を書く |
| 書き方 | DSL（要素・関係・ビューを別に書く） | マクロ（図の中に、要素と関係を書く） |

**図ごとに要素を書く理由**: PlantUMLの`!include`で取り込めるのは、標準ライブラリ（`<C4/...>`）だけである。ファイルとURLの取り込みは、セキュリティ上、拒否される（#622）。そのため、この例では、共通の定義ファイルを使わず、図ごとに、要素と関係を書いている。要素を直すときは、それを使う図を、すべて直す。1つのモデルから、複数の図を作りたい場合は、Structurizr版を使う。
